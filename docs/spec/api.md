# API

Every endpoint the web app (and the iOS app) uses. The server is the source of truth: routes are listed in `server/src/main.rs` (`fn router`), each handler next to the feature it belongs to. Every change follows the compatibility rules in [releasing.md](../operations/releasing.md): the API only grows.

All endpoints are under `/api`. Auth is `Authorization: Bearer <token>`, which works the same way for a mobile app. Errors look like `{"error": "human readable"}`. Anything that checks a password or a recovery key (signing up and in, unlocking, recovery, changing the password or username, setting a recovery key, adding a passkey, deleting the account) can answer `503` "napsack is busy. Try again in a moment." when too many such checks are waiting for their turn; try again shortly. Native apps also send `X-Napsack-Client: ios/<version>+<build>`; see [releasing.md](../operations/releasing.md) for the compatibility rules every change has to follow.

| `GET  /ws` | WebSocket. First frame: `{"type":"auth","token":"..."}` |

Clients send `{"type":"visibility","visible":bool}` (no push while on screen), `{"type":"typing","to"|"group":id}`, and `{"type":"ping"}` (answered at once with `{"type":"pong"}`, so the app can tell a dead connection; the web app pings every 25 seconds while on screen) over the socket. More than 60 frames in 10 seconds closes the socket, as does falling 256 events behind (a client that stopped reading); the client reconnects and refetches, as after any dropped connection. WebSocket events: `typing {from, group_id}`, `presence {user_id, active, last_seen_at}`, `ready`, `message`, `message_updated`, `read {by, at}`, `friends_changed`, `group_message {group_id, message}` (new or updated; only to members who were in the group when it was sent), `groups_changed {group_id}`, `group_read {group_id, user_id, last_read_id}`, `announcement {announcement}` (the Admins' current announcement, or null, to everyone connected). On every `ready` the client refetches its state, so missed events while disconnected don't matter.

Messages include `format`, the encryption scheme, so clients know how to read them: texts and pics are written as format 2 and format 1 stays readable; group messages are format 0 (not encrypted). The schemes are in [how-napsack-works.md](../how-napsack-works.md).
